# CAD Modeler: handoff notes for agents

A single-part parametric 3D modeler that copies the look and feel of Autodesk Fusion 360. It's an Electron desktop app wrapping a Vite web front end, using three.js for the viewport and replicad (OpenCascade compiled to WASM) as a real B-rep kernel. Units are mm and **Z is up**. The owner is a single user on Windows 11 with an RTX 3080, building this across many sessions.

`README.md` covers the user-facing features. This file covers what you need in order to work on the code.

## Before you start
1. **Read new bug reports and feature requests first:** `node tools/bugstatus.cjs` lists the open ones (untouched + in work; feature requests live in `feature-requests/`, same layout, from the in-app Feature request button; `history` prints everything finished); each is `bug-reports/<time>_<memo>/README.md` with the user's memo, the last 5 minutes of clicks and keys, app state, a screenshot and the design file. The user files these from the in-app **Bug report** button and expects you to pick them up. **Keep the status current:** `node tools/bugstatus.cjs set <name or prefix> in-work "what you found"` when you start, `resolved "what was wrong and what changed"` when it's fixed and tested (for a feature: what was built and where to find it; these notes are the History tab, the user's record of every change) (it writes `<report>/status.json`; the user sees it in Bug report > Reports… and the badge on the button counts open reports). Don't mark something resolved that you couldn't reproduce or test; leave it in work with a note. Reports with a `from.txt` came from a friend's copy (they send with `Send Bug Reports.bat` to the GitHub `bugs` branch; the owner pulls with `Pull Bug Reports.bat`): they have **no design.cadm.json** (design files never go to GitHub), so reproduce from the event log and screenshot.
2. **Run the tests.** All seven should pass:
   `for t in kernel solver io cfdlink materials bugreport fasteners assembly stock fealink; do node tests/$t.test.mjs; done` (fasteners takes about 20 s; fealink runs a real FEA Sim solve, ~5 s, when Python + gmsh are installed, skip it with `FEA_SKIP_E2E=1`)
   Plus `node tests/units.test.mjs` (display units / typed-value parser; <1 s), `node tests/parts.test.mjs` (Parts folder store; <1 s), `node tests/hybrid.test.mjs` (inserted designs: volumes vs the source, nesting, loop detection; ~1 s), `node tests/startpage.test.mjs` (start page offer, empty leftover tabs; <1 s), `node tests/profiles.test.mjs` (sketch profiles with overlapping / duplicate lines; <1 s), `node tests/section.test.mjs` (section area / perimeter / second moments vs closed form; ~2 s), `node tests/chains.test.mjs` (sprockets, chain closure vs the chain-length formula, seat interference, belts; ~3 s), `node tests/gears.test.mjs` (gear geometry, meshing by B-rep interference, wizard plans, motion links, URDF mimic; ~20 s), `node tests/generative.test.mjs` (airfoils, 2D flow CPU solver + panel method, shape optimization; ~30 s) and `node tests/robotexport.test.mjs` (robot export; runs `tools/check_robot_usd.py` through Python if `usd-core` is installed)
3. **Run `npm run smoke`.** It builds, starts Electron headless, checks that the kernel loads, exercises IPC (case writing and reading, solver status, bug-report saving, path-traversal guards) and quits. It deletes the artifacts it creates.
4. After touching closing / saving / tabs: `node tools/exit-check.cjs` (after a build). It runs the real desktop app in a throwaway profile (`--user-data=<tmp>`, so never the user's tabs; it also skips the single-instance lock) and checks the save prompt: Cancel keeps the window, Don't Save closes it, and the next start is one blank design; then two simulated crashes check that empty leftover tabs are dropped and never offered as Continue.

## Running
| Command | What it does |
|---|---|
| `Start CAD Modeler.bat` | The user's launcher. Runs npm install if needed, rebuilds `dist` if `src` is newer, then starts Electron detached. No server. |
| `npm start` | Same as the .bat, in the foreground with logs |
| `npm run desktop:dev` | Vite on :5180 plus Electron with hot reload |
| `npm run dev` | Browser-only Vite dev server on :5180 (handy with the preview pane) |
| `npm run package` | electron-builder NSIS installer and portable exe. Output to a folder **outside Documents**: antivirus caused EPERM renames inside the project. See `docs/desktop.md`. |

**Don't leave dev servers running.** Earlier agents left Vite servers on ports 5180–5193 and the user noticed. Stop anything you start, and tell any sub-agents not to start servers. The launch config for the preview pane lives in `C:\Users\Austi\Documents\.claude\launch.json` (entry `cad-modeler`, which runs `node node_modules/vite/bin/vite.js <project root>`). The npm/npx shims break on the space in "CAD Modeler", so call node directly.

### Data model
- **Document:** `{ id, kind, name, features[], marker, counters, hidden[], appearances{bodyId: {materialId, color, finish}}, studies[], assembly }`. It autosaves to localStorage key `cadmodeler.doc.v1`.
  - `id`: stable design id (`newDocId()`), generated once and saved in the file; older files get one when read (`fromStored` in main.js) and keep it from their next save. Used for loop checks across renames (Save As copies it).
  - `kind`: `"part" | "assembly" | "hybrid"` (file-structure nomenclature, user 2026-10-09). `docKind(d)` in hybrid.js: any `insert` feature → hybrid; else a stored part / assembly is kept; old docs without `kind` → assembly if they have components or are a fresh "Untitled assembly", else part. `regen()` re-derives it (deleting every insert turns a hybrid back into a part). Start page New Assembly sets `"assembly"`. Shown as the tab icon (body / component / hybrid icon, tooltip names the type), the browser root row (icon + "Assembly"/"Hybrid") and the Parts panel's open-design cards.
  - **Hybrid designs (inserted designs):** dropping a saved design onto the viewport (Parts bin card, open-design card, a `.cadm.json` from Explorer, or File > Import of a design file) runs `insertDesignDoc` in main.js: it adds an `insert` feature `{ id, type: "insert", name, source: { id, name, file }, snapshot: { id, name, kind, features, marker, appearances }, translate: [x,y,z] }` (built by `makeInsertFeature`). The snapshot is a frozen copy (no live link/update yet); the kernel replays it with `evaluate()` (cached per snapshot object / content hash) and adds its bodies as new bodies at the origin + `translate` (names: the design name, or `Design · Body1` for several; `b.inserted = {feature, source, body}`; appearances carried via `stockAppearance` → `doc.appearances` auto; `meshTol` / `fastener` kept). Nested inserts recurse (depth cap 16). **Loop rule** (`insertLoop`): refused (toast) when the source is the target (same `id` or same file path, case-insensitive) or any design in the source's inserted tree (recursively through snapshots, by id or file) is the target. The open-design list hides the active tab. Opening designs stays on File > Open / double-click in the bin. OS drops get their path through `platform.droppedFilePath` (preload `webUtils.getPathForFile`). Double-clicking an insert in the timeline only explains it (no edit dialog).
  - `assembly`: `{ components[], joints[] }` (see `docs/assembly.md`). Document-level, not in the timeline; edits go through `pushUndo()`/`save()` like everything else. Old docs without it get `emptyAssembly()` (via `newDoc()` spread, and `normalizeAssembly` on first use). Component visibility lives in `hidden[]` as `asm:<componentId>`.
  - Bodies keep their modelled coordinates; a component's placement is a matrix on the body's three.js group (`vp.setBodyTransforms`), so articulating never re-meshes. `show()` sets `vp.bodyXforms` before `setState`.
  - `studies[]`: in-app CFD studies `{ id, name, casePath, folderName, settings, bodies, createdAt, status, results{Cd,Cl,Cs,forces_N} }`. The results themselves stay in the case folder. Static stress studies have `kind: "fea"`, `settings{bodyId, fixtures, loads, gravity, quality}` (face references, so Edit Study can reopen them) and `results{status, maxVonMises_MPa, maxDisplacement_mm, minSafetyFactor}`. FEA studies store `bodySig` (volume + bounds of the analysed body at solve); older ones get `meshBounds` from the results mesh on first open. `studyStale(sd)` → `"missing"` (body gone: results won't open) / `"changed"` (out of date: dimmed row + toast) / null. The Simulations folder shows only in the Simulation workspace, and leaving that workspace closes open results. Studies are written into the design that started them (`owner` captured in `feaCtx` / `openCfd`, saved with `saveDocAnywhere`), and `leaveDoc` closes the FEA / CFD study dialogs, so nothing crosses tabs (bug report 2026-10-08 20:50).
  - `analyses[]`: Section Analysis `{ id, name, plane{origin,xDir,normal} (world, stored when picked, not re-resolved), planeLabel, offset, flip, cap: "hatch"|"solid"|"none" }`; the cut plane's normal points at the removed side. Visibility is `hidden[]` entries `sec:<id>` (plus folder `analysis`); only one shows at a time.
  - The Electron origin `app://local` has separate storage from `localhost:5180`.

## Gotchas
Each of these cost real debugging time.
- **replicad `shape.faces` / `shape.edges` are O(n²)** (explorer + linear `IsSame` dedupe): 0.6 s / 8.5 s on a 1,700-face STEP import, per call. `initKernel` replaces both getters on `R.Shape.prototype` (`patchTopoLists` in kernel.js: buckets by `ReplicadShapeHasher.HashCode`, same first-occurrence order, cached per `shape.wrapped`, returns a fresh array of the cached wrappers). Wires keep the original getter (replicad's `makeNonPlanarFace` deletes the edges it gets). So **never `.delete()` a face/edge from `.faces`/`.edges`**. `TopTools_IndexedMapOfShape` isn't constructible in this WASM build. Test: end of `tests/kernel.test.mjs`. Per-shape derived data (e.g. assembly.js `planarFaces`) can be cached in a WeakMap keyed by the shape.
- **Don't create/dispose three.js materials per mouse move.** Disposing a material whose program has no other users frees the program, and the next frame recompiles it (~4-12 ms each). The sketch overlay (`setSketchOverlay`, `ovCache`), highlights and joint glyphs reuse objects / cached materials (`hlFaceMat`, `hlLineMat`, `userData.cached` keeps `disposeGroup` off them). Never share a body's `position` attribute with a temporary geometry: disposing the temp frees the body's GPU buffer and the whole mesh is re-uploaded (the old face highlight did this on every hover).
- **Hosts (assembly placement of sketch-derived things):** the kernel stores `host` (body id) on `st.sketches[id]` (sketch on a face, or on a construction plane that has a host), `st.planes[id]` (plane from a face) and on bodies created by extrude / revolve from such a sketch or face (`tagHost`). `transformsFor` in assemblyui maps hosted bodies to their host's component transform and adds `sk:<id>` / `pl:<id>` keys that the viewport applies to sketch views and plane quads; `enterSketch` edits on `transformPlane(plane, host xform)` (2D sketch coordinates are the same in both frames) and keeps the stored plane in modelled coordinates (`app.sk.modelPlane`). `itemFrame` places arrows in the placed frame. Booleans still run in modelled coordinates, so an auto-join can overlap bodies by their modelled positions.
- **Cut edges / Intersect** (feature request 2026-10-18 18:42): `K.sectionEntities(shape, plane, bounds)` (cutter-face intersect + `projectFaceEdges`; [] when the plane misses or only touches); `scheduleCutEdges()` in main.js runs it per visible body one tick at a time after `enterSketch` (plane moved into each body's modelled frame with `invertRigid`), cached in `cutCache` per shape + plane; `sketcher.setCutEdges` draws them dashed and adds them to model snaps; `sketchIntersect` / `sketcher.addCutEdges` adds them as fixed projected entities. Bodies with `meshTol` (threads) are skipped.
- Join / New previews of extrude and revolve build only the tool (`K.featureTool`), never the boolean (runPreview); the tool draws in its source's placement (`setPreviewTool(shape, color, matrix)`).
- **Booleans are patched** (`patchBooleans` in kernel.js): `R._3DShape.prototype.fuse/cut/intersect` run BRepAlgoAPI with `SetNonDestructive(true)` and throw a readable error when OCCT fails (replicad's own run destructive and return null shapes, "This shape has not type, it is null"). Note replicad `clone()` is NOT a deep copy (same TShape, new handle), so cached shapes are shared by every rebuild. `regen()` retries once with `K.clearShapeCaches()` when new feature errors appear and logs `feature errors retried` (with `K.lastFeatureError.stack`). Debug hooks: `__K` (kernel), `__runPreview()` (runs a pending preview; rAF is paused in hidden panes).
- **Incremental replay:** `K.evaluate` caches the state after each timeline prefix (`prefixCache`, key = chain of content hashes per feature, big embedded strings memoized in `bigStringHash`; LRU 96; cleared by `clearShapeCaches`). It returns clones, so callers may mutate their state. Features edited in place (Suppress) are seen because hashes are recomputed each call. Anything that changes a shape in place would poison the cache: always build new shapes.
- **Orthographic camera eye** sits `orthoSpan()` behind the target (near > 0), not at `view.dist`: with the eye at dist, parts behind it were drawn (negative near) but GTAO blacked them out. Use `vp.persp.position` for "the eye at view.dist" (setPivot, headlight).
- Grid shader fades each line family by its `fwidth` (no moire at grazing angles). Studio environment's horizon band brightened; aluminium 6061 metalness 0.85.
- Consumed sketches are auto-hidden (okCommand); a feature edit sets `c.showSketches`, which `show()` / `applyVisibility()` force visible.
- Bash heredocs on this machine may turn a `\n` inside Python string literals into a real newline when patching JS: use String.fromCharCode(10) or the Edit tool for such strings.
- Editing a feature activates its first selection field (all fields are filled, so otherwise nothing is pickable).
- Sketch mode switches the camera to orthographic without saving the preference (`setCameraMode(m, { persist: false })`, `prefs.sketchOrtho`, restored in `finishSketch`).
- Picking uses per-B-rep-face / per-edge bounding spheres (`vp.faceHits` / `vp.edgeHits`, built lazily on the body view) instead of three.js raycasts over every triangle / segment; results match the raycaster.
- replicad **`makeCompound` deletes its input shapes**. Always pass clones. This silently destroyed bodies during multi-body export.
- replicad **transforms (`translate`, `scale`, …) delete the original**; clone first. Booleans (`fuse`, `cut`, `intersect`) don't delete their inputs.
- `mesh().faceGroups` and `meshEdges().edgeGroups` are in the same order as `shape.faces` / `shape.edges`. `faceId` is a hash, not an index.
- OCCT's thick-solid shell silently returns its input unchanged when the removed face is tangent to a kept face (next to a fillet). The kernel detects the unchanged volume and falls back to `shellByOffset`.
- In this WASM build, replicad's `importSTL` throws. The kernel reads STL with `StlAPI_Reader` and builds the solid with `makeSolid`. Generated STL must have a non-blank header and real normals, or OCCT misdetects it as ASCII.
- There's no IGES in this OCCT build.
- three.js Line raycast hits have no `distanceToRay`; use `ray.distanceToPoint(hit.point)`.
- During fillet/chamfer/shell previews the viewport displays the **result** body. Picks must go through `mapItem()` back to the base body. Forgetting this caused the user's "chamfer picks the wrong edge" bug.
- `face.normalAt(face.center)` throws on curved faces whose centroid is off the surface (a cylinder's): use `K.faceNormal(face)` (falls back to the mid-parameter normal). It broke picking a pulley as a mesh partner.
- `main.js` sometimes ends up with CRLF line endings. Python patch scripts should normalise `\r\n` first, or their string matches fail.
- In Claude's browser preview pane, `requestAnimationFrame` doesn't run while the pane is hidden. Camera animations stall and screenshots time out on the first try, so retry. Drive tests by script through `__app` / `__vp` / `__sk` and `vp.handlers.click({clientX, clientY})`, using `vp.worldToScreen(...)` for coordinates. The pane width changes between calls, so recompute coordinates inside the same script.
- When sketching, the overlapping origin-plane quads make "click the XY plane" unreliable. Compute sketch coordinates with `K.to3D(__app.sk.plane, [u, v])`.
- **Helical threads and OCCT.** Threads are `R.twistExtrude` of the thread cross-section (a closed spline r(θ)): about 50 ms, valid solid. Avoid every other route:
  - Booleans against that helicoid are seconds at best. A tip chamfer by intersection took 16 s and returned an empty shape; sweeping a tooth along `makeHelix` and fusing it with a core gave the same result.
  - So modeled fasteners are **compounds of touching solids** (head + thread). Only nuts and set screws cut into a thread (about 1 to 2 s).
  - `shape.boundingBox` on a thread costs about 3 s, so the kernel never asks for it on fastener shapes.
  - The default 0.01 mm tessellation of a thread gives ~10^6 triangles. `body.meshTol` (P/4) is used for display, and `exportSTL` meshes threaded bodies at meshTol/2.
  - Built parts are cached by parameters (`fasteners.js`) and placed shapes by placement (`kernel.js`), so a timeline replay reuses the same shape objects and `meshBody`'s WeakMap cache hits.
- replicad's `geomType` for a cylindrical face is `"CYLINDRE"` (French), not "CYLINDER". Circular edges are `"CIRCLE"` and are often split into two half-circle edges.
- Shop Stock profiles are built as one replicad `Drawing` (`drawRoundedRectangle(...).cut(poly).cut(drawCircle)...`) and extruded once. Interior holes (bores, tube bores, cored pockets) survive Drawing cuts fine here (volumes are checked in `tests/stock.test.mjs`); the 3030 inch T-slot (242 faces) takes ~0.4 s to build, then it's cached. A face's `center` is its centroid, so a part placed on a face with a hole sits off the face's middle (same for fasteners).
- `makePolygon` returns a **Face**; pass `.outerWire()` where a wire is expected, or OCCT throws a bare `WebAssembly.Exception`.
- Claude's Edit tool may save files with CRLF line endings on this machine. Normalise `\r\n` in patch scripts.
- **Assembly placement is a matrix on each body's group** (`grp.matrixAutoUpdate = false`). Anything that draws or measures a body in world space must apply it: highlights use `vp.followBody(obj, bv)`, shadow/AO proxies copy `grp.matrix` (the proxy scene doesn't auto-update matrices), bounds use `vp.bodyWorldBox(bv)` (cached local box × matrix), GLB export applies `grp.matrix` to the cloned mesh. `vp.pick` returns `point` (world) plus `localPoint` (modelled), and face/edge indices still refer to the modelled shape, so kernel references stay valid.
- Primitive features (box, cylinder, sphere) are always built at the origin, and `operation: "auto"` joins a second primitive into the first body. For assembly tests use `operation: "new"` and let joints / Move place the parts.
- OCCT's vertex normal at a surface singularity (a revolved dome's pole, a cone's apex) can come back flipped and shows as a dark spot. `meshBody` runs `fixSingularNormals` (replace normals that disagree with their triangles' area-weighted normal); `tests/kernel.test.mjs` checks the user's dome (`tests/fixtures-dome.json`).
- **Sketch profiles and bridges:** `sketchLoops` splits a face cycle that walks the same edge both ways (`splitBridges`: a line joining an inner loop to an outer one without dividing the region) and keeps the counter-clockwise parts; the hole returns through the region booleans. Before, the ring became one face with a zero-width slit and every extrude made an invalid body (two coincident faces), which silently broke later booleans (bug report 2026-10-20 19:27; `tests/profiles.test.mjs`). The bridge's end points still split the walls they touch into two coplanar faces (cosmetic).
- Sketch Dimension accepts circle/arc pairs (`radialGap` when concentric: |r1 − r2|, in solver.js residual + `measureDim`; else centre-to-centre `distance`), circle/arc + point (`distance` to the centre) and circle/arc + line (`pointLine` from the centre).
- **Sketch press vs drag:** pressing on draggable geometry starts a handler drag (`sketcher.down`), but the viewport only forwards `drag` once the pointer moved > 4 px, and `handlers.up(e, moved)` → `dragEnd(e, false)` turns a press without movement into `click` (select). Before, free lines could never be selected, so Delete did nothing (bug report 2026-10-20 18:38).
- Sketch annotations (`#annot` dimension labels, constraint glyphs) take clicks. While a drawing tool is active `#annot` has class `passive` (set in `Sketcher.setTool`) so clicks reach the tool; select, Sketch Dimension and constraint tools keep them clickable.
- Feature drag arrows: a DEFS entry's `arrow(values, baseState)` returns `{ origin, dir, key, scaleValue?, min?, step? }`; the arrow sits at origin + dir·value·scaleValue. Fillet / chamfer use `edgeArrow()` + `K.edgeFrame` (bisector of the two faces, flipped for concave edges via a point-in-solid test with `measureDistanceBetween`, which is 0 inside a solid), so the tip rides on the new surface. Shell uses `shellArrow()` + `K.shellFrame`: the removed face's rim point nearest the pick (`localPoint`, which `mapItem` now carries over), pointing along the bordering kept face's inward normal, so the tip sits on the new inner wall. Never anchor arrows at a face's `center` on curved faces (it's the centroid, off the surface); `K.faceFrameAt(shape, idx, near)` gives an on-face point + outward normal.
- `planeQuad()` shares one `userData` object between the quad group and its mesh and keeps `.mesh` on it. Assign into it (`Object.assign`), never replace it: replacing it in `setPlanes` made every highlight/pick throw once a construction plane existed, which aborted `regen()` before the timeline redrew and blocked sketching on planes (bug reports 2026-10-10 08:36).
- Assembly commands are `app.cmd = { kind: "asm", ... }` with generic hooks that main.js forwards: `pickKinds()`, `onPick(item)`, `highlights()`, `onOK()`, `onCancel()`. `cancelCommand` calls `onCancel` *after* clearing `app.cmd`, which restores the document's placement.
